# Constrained Gemini structured-output fallback

The change routes only deterministic-parser `unsupported_intent` results to an isolated Gemini planner. That planner sends a fixed structured-JSON request through the official SDK with no tools, no retries, an abortable timeout, `store: false`, and only the message text, current time, and time zone; parsed output is locally schema- and semantically validated before returning to the assistant. Gemini provenance survives target selection, and create, update, delete, attendee, and reminder mutations all require confirmation; raw `output_text` is neither logged nor persisted. Two **confirmed** freshness gaps remain in that confirmation path: recurring writes are not bound to the reviewed series master version, and updates reuse pre-confirmation conflict warnings.

Watch for: **confirmed** model-proposed recurring series changes can proceed after the series master changes, and **confirmed** new conflicts can be omitted from a confirmed update.

**Verdict**: NEEDS_CHANGES

## High-level view

The fallback boundary accepts only text, time, and time zone; it has no injected calendar, OAuth, Discord, or state capability. Structured JSON and strict local validation constrain its output to a calendar command while keeping the raw provider response transient.

Model provenance is retained through the ambiguous-target selection path, which keeps model-generated mutations behind an explicit confirmation gate. The confirmation freshness model is **confirmed** incomplete for recurrence and scheduling conflicts: it checks the selected occurrence version while accepting a newly fetched series master, and it treats the original conflict result as current.

## Recurring confirmation is not bound to the series master — High, confirmed

`PendingMutation` records one `expectedEtag`, populated from the selected event at `src/application/calendar-assistant.ts:865-866`. For `series` and `all_future` work, confirmation fetches the master at `:919-923`, only verifies that it has a nonempty ETag, promotes it to `writeTarget` at `:931-934`, and writes it with that freshly fetched ETag at `:991-1002`; split and truncation paths likewise receive the fresh master at `:973-988`.

```
review: selected occurrence ETag ──stored──> confirmation
                                              └─ fresh master ETag ──write
                                                   (never compared to review)
```

A master change that does not also invalidate the selected occurrence's saved ETag is accepted after review, allowing a model-proposed whole-series or all-future mutation against revised series data without a new confirmation. Capture master and occurrence ETags when queuing the action, compare both after reload, and use the reviewed master ETag for the API precondition so a post-check race fails closed. Not tested: a stable occurrence with a changed master ETag for either series-update or all-future flows; the existing stale-ETag test changes only the selected event (`test/calendar-assistant.test.ts:398-419`).

## Confirmed updates retain pre-review conflict warnings — Medium, confirmed

Initial target resolution computes conflicts from the proposed patch at `src/application/calendar-assistant.ts:529-532` and saves the warning in the pending mutation. At confirmation, `executeMutation` reconstructs its decision from `mutation.warnings.includes("calendar_conflict")` at `:935-937`; it does not call `findConflicts` again before writing. The confirmation and completion messages also render the stored warning at `:1052-1061` and `:1168-1173`.

A new event can overlap the proposed time while the selected event ETag remains unchanged, so the confirmed mutation executes without disclosing that conflict; a resolved conflict remains reported as present. Recompute conflicts from the current target and actual patch, use that result for the decision and messages, and require a new confirmation if the warning set differs from the reviewed action. Not tested: conflict insertion or resolution between the original review and confirmation.
