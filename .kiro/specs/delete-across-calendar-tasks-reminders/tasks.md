# Implementation Plan

## Scope

Implement the validated unified named-delete path for `delete_task` actions with `scope: "single"` and a title selector. Resolve the authenticated owner's eligible Google Calendar events, legacy local tasks, and scheduled reminders completely before choosing a result; use canonical title/date matching; fail closed on incomplete reads; route an exact target through its existing domain safety path; and require explicit selection for ambiguity. Preserve all explicit, bulk, deterministic, fallback, lifecycle, and provider-safety behavior outside this narrow route.

Use fixed clocks, in-memory repositories, owner-scoped fakes, and fake Calendar gateways in tests. Do not add a dependency solely for this feature, access the active `.env`, require OAuth/Gemini/network access, or start a development server or watcher.

    - Create an application-level named-delete resolver/handler (for example `src/application/named-delete-resolver.ts` and `src/application/named-delete-handler.ts`) with narrow request, candidate, resolution, and pending-payload types.     - Implement one canonical selector normalizer for this resolver: Unicode `NFKC`, collapsed whitespace, trimmed locale-independent lowercase, splitting on every non-letter/non-number Unicode character, removal of only the specified generic command/record terms (`a`, `an`, `appointment`, `appointments`, `class`, `classes`, `event`, `events`, `meeting`, `meetings`, `my`, `on`, `reminder`, `reminders`, `schedule`, `schedules`, `task`, `tasks`, `the`, `to`), date terms removed through date parsing, first-seen de-duplication, and invalidation when no meaningful terms remain. Match every selector term against a complete candidate title/summary token; preserve Unicode letters/numbers and original display text; do not add stemming, fuzzy distance, broad substring, or cross-field matching. Keep existing deterministic domain-specific matchers unchanged.
    - Read the three eligible sources completely before deciding or invoking an adapter:
      - active owner-scoped legacy local tasks, using the existing repository and single-transition eligibility; for an unscoped request do not add a future-time gate, and for a supplied date compare the task's local due date in its stored time zone;
      - active owner-scoped scheduled reminder items, materializing occurrences through the existing cleanup horizon; for an unscoped request require `dueAt > now`, and for a supplied date compare the stored `scheduledDate`, including the existing current/past date-scoped behavior;

    - Distinguish an explicitly unconfigured optional Calendar gateway (`skipped`) from a configured Calendar read failure or unusable matching event/empty ETag (`read_failure`/`unsafe_calendar`). A repository or required Calendar read failure must block the whole resolution, return a safe retry/review result, and perform no local-task, reminder, or Calendar mutation; never use a partial result or stale/local/agenda cache as proof of no match.
    - Return stable candidate snapshots containing only the domain identity and freshness data needed by the application: legacy task ID/revision, scheduled reminder item ID/revision/series metadata, or Calendar ID/event ID/ETag/recurrence/guest data plus display fields. Use deterministic ordering for review display only, never as authorization.
    - Implement zero/exact/ambiguous branches. Zero candidates produce the existing safe no-match behavior with no write. Exactly one candidate invokes only that domain adapter using the captured identity/freshness token. Multiple candidates in one or more domains create no mutation and expose the complete safely visible candidate list for explicit selection; do not prefer Calendar, reminders, or tasks and do not silently turn a single named request into a bulk operation.

Render domain/title/date/calendar labels only; never expose IDs, ETags, OAuth values, encrypted payloads, or raw provider errors. Handle `choose`/`cancel` before domain-specific pending handlers, consume selections once, revalidate owner/status/date/revision/ETag, and route exactly one selected candidate to one adapter. Invalid, expired, cancelled, owner-mismatched, or stale selections must fail closed with no mutation or cross-owner disclosure.
    - Add `LocalTaskAssistant.handleResolvedNamedCancellation` or equivalent. Use the captured task ID and expected revision with the existing owner-scoped cancellation/transition, audit, reply, and current model-proposed single-transition confirmation policy; do not title-search again or alter deterministic task selectors.
    - Add `ScheduleAssistant.handleResolvedNamedReminderCancellation` or equivalent.
